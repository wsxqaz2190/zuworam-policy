# 주워람 개인정보처리방침 웹페이지

GitHub Pages에 게시할 수 있는 단일 HTML 페이지입니다. 제공된 HTML 양식을 유지하고
앱의 `lib/screens/policy/privacy_policy_screen.dart`와 동일한 개인정보처리방침
11개 항목을 반영했습니다. 시행일은 **2026년 11월 8일**입니다.
문안 원본은 `docs/privacy_policy_draft_2026_11_08.md`이며, 원본의 내부 검토 메모는
공개 HTML에 포함하지 않았습니다. 기존 `docs/PRIVACY_POLICY.md`는 사용하지 않았습니다.

계정 삭제 요청 안내와 Gmail·메일 앱 작성 및 이메일 복사 기능을 유지했습니다.
앱의 탈퇴 경로는 **내 정보 → 설정 → 계정 탈퇴**로 안내합니다.
긴 본문 표는 모바일에서 항목별로 세로 배치됩니다.
이 파일을 준비한 것만으로 기존 GitHub Pages가 갱신되지는 않습니다.

## 파일

- `index.html`: 본문, 목차, 스타일을 포함한 독립 실행 페이지
- `.nojekyll`: GitHub Pages에서 정적 파일을 그대로 제공하기 위한 파일

별도 빌드, 외부 폰트, 페이지 로그인, 분석 도구가 필요하지 않습니다.
이메일 주소 복사에만 페이지 내부 JavaScript를 사용하며, JavaScript가 꺼져 있어도
본문과 메일 작성 링크, 문의 이메일 주소는 표시됩니다.
로컬에서는 `index.html`을 브라우저에서 열어 확인할 수 있습니다.

## GitHub Pages에 올리기

이미 게시한 페이지가 있다면 같은 저장소·경로의 `index.html`을 이 파일로 교체합니다.
새로 게시하는 경우에는 아래 절차를 사용할 수 있습니다.

1. 정책 전용 공개 저장소를 만듭니다. 예: `zuworam-policy`.
2. 이 폴더의 `index.html`과 `.nojekyll`을 새 저장소 최상위에 올립니다.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Deploy from a branch**에서 게시할 브랜치와 **/(root)**를 선택해 저장합니다.
5. 배포 완료 후 **Visit site**로 접속하고, 로그인하지 않은 브라우저에서도
   본문과 메일 작성 링크가 표시되는지 확인합니다. Gmail 작성 링크의 받는 사람·제목·본문과
   이메일 주소 복사 버튼도 확인합니다.
6. 생성된 HTTPS 페이지 주소를 Play Console의 개인정보처리방침 URL에 입력합니다.

GitHub의 파일 보기 주소나 Raw 파일 주소 대신 **Pages 웹페이지 주소**를 사용합니다.
앱 프로젝트의 기존 운영 배포와 구분해 정책 전용 저장소에서 관리할 수 있습니다.

공식 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## Play Console의 계정 삭제 URL

배포된 GitHub Pages 주소 끝에 `#account-deletion`을 붙이면 상단의 계정 삭제
요청 안내로 바로 이동합니다. 이 전체 주소를 **계정 URL 삭제** 항목에 입력합니다.
개인정보처리방침 URL에는 기존 페이지 주소를 사용합니다.

## 이메일 작성 및 주소 복사

- **Gmail에서 작성**: 브라우저의 새 탭에서 Gmail 작성 화면을 엽니다. 기본 메일 앱 설정이
  필요하지 않으며, Gmail 로그인이 필요할 수 있습니다. 발신 계정이 주워람 가입에 사용한
  Google 계정인지 확인해야 합니다.
- **메일 앱에서 작성**: 기존 `mailto:` 링크로 기본 메일 앱을 엽니다. 기기나 브라우저에
  메일 앱 연결이 설정되어 있어야 합니다.
- **이메일 주소 복사**: `zuworamhelp@gmail.com`을 클립보드에 복사하고 결과를 안내합니다.
  HTTPS 또는 localhost에서 확인하세요. 클립보드 API가 없거나 권한이 거부되면
  주소가 선택된 읽기 전용 입력란을 표시하므로 직접 복사할 수 있습니다.

두 작성 링크 모두 받는 사람·제목·본문을 미리 채웁니다. 사용자는 본문의 가입 이메일
주소를 채우고 내용을 확인한 뒤 직접 전송해야 합니다.
웹페이지에서 메일을 자동 전송하거나 서버 계정을 직접 삭제하지 않습니다.
운영자가 접수한 요청을 확인하고 본인 확인 및 실제 삭제를 처리해야 합니다.
